# 運用

## ふだんの動き

| 時刻(目安) | 起きること |
|---|---|
| MSMの初期時刻(00, 03, … 21UTC) | 気象庁がMSMを計算 |
| 初期時刻の約3.5〜5時間後 | 京大アーカイブに掲載される(2026年10月20日の実績) |
| その後30分以内 | Worker が Actions を起動 → 新しい初期値を見つけて計算・保存(数分) |
| 掲載がない回 | Actions は「新しい初期値はありません」と出してすぐ終わる |

予備として、Actions 自身の定期実行(3時間ごと、40分)も入っています。
GitHub の定期実行は、混雑時に遅れることがあります。また公開リポジトリで60日間コミットがないと、
定期実行は自動で止まります。Worker からの起動(workflow_dispatch)はこの影響を受けません。

## 使う量(1日8回更新・60日保存)

| 項目 | 量 | 無料枠の目安 |
|---|---|---|
| Actions の実行時間 | 1回2〜4分、確認だけの回は1分未満 | 公開リポジトリは無制限 |
| ダウンロード | 1回約385MB(気圧面+地上)、1日約3GB | — |
| R2 の保存 | 1回約14MB、1日約110MB、60日で約6.7GB(75日で約8.3GB) | 10GB |
| R2 の書き込み | 1回13件、月約3,200件 | 月100万件 |
| R2 の読み出し | 閲覧1回で数件 | 月1,000万件 |
| Worker の起動 | cron 月約1,440回+閲覧時のデータ取得 | 1日10万回 |
| 閲覧1回の通信量 | 予報時刻1つで約0.6MB(切り替えるたびに追加) | Cloudflare からの配信は無料 |

数値は2026年10月時点の各サービスの公開情報にもとづく目安です。条件は変わることがあるので、ときどき確認してください。

## 状態の確かめ方

- **Actions の画面**:実行の成否とログ。失敗が続くと、GitHub から登録メールに通知が届きます。
- **Worker のログ**:`cd worker && npx wrangler tail` で、起動の失敗(トークン切れなど)が見えます。
- **画面の上端**:表示中の初期時刻と作成時刻が出ます。最新の初期時刻から6時間以上新しいものが来ていなければ、どこかで止まっています。

## 困ったとき

| 症状 | 原因と対処 |
|---|---|
| `CERTIFICATE_VERIFY_FAILED` | 京大サーバーの証明書が変わった可能性があります。`batch/certs/` の中間証明書・ルート証明書を新しいものに入れ替え、`rish_ca.sh` の指紋(EXPECTED)を更新します。ルート証明書は、信頼できる環境(WindowsやmacOSの信頼済みストアなど)の値と指紋を照合してから入れてください。 |
| `ルート証明書の指紋が一致しません` | `batch/certs/` のファイルが書き換えられています。リポジトリの履歴を確認してください。 |
| ダウンロードの失敗が続く | 京大アーカイブの停止や遅れ。アーカイブのトップページのお知らせを確認します。自動で再試行(3回)します。 |
| `AccessDenied`(R2) | R2の鍵の権限か期限。GitHub Secrets の3つを確認します。 |
| Actions が起動されない | GitHub トークンの期限切れの可能性があります。トークンを作り直し、`npx wrangler secret put GH_TOKEN` で入れ直します。 |
| 画面に「データを読み込めませんでした」 | R2 に `index.json` が無い(初回の実行前)か、Worker の R2 の紐付け(`wrangler.toml` の `bucket_name`)が違います。 |

## よくある作業

### 過去の初期値を作り直す
Actions の **Run workflow** で、init に `2026102009` のように初期時刻(UTC)を入れます。
京大アーカイブの最新フォルダは約1週間分しか残らないので、それより古いものは作れません。

### 保存日数を変える
GitHub の Variable `RETENTION_DAYS` を設定します。次の実行から、期限を過ぎた分が削除されます。
R2 の無料枠(10GB)を超えないよう、1日あたり約110MBで計算してください(85日程度が上限)。

### 総合の係数や色の区切りを変える
`web/index.html` の `totalCore()`(係数と高度係数)と `CAT`(色の区切り)を書き換えて、`npx wrangler deploy` します。
総合の計算はブラウザで行うので、バッチの再計算は要りません。

### 「並」の目安や計算方法を変える
`batch/turbmap/diag.py` の `THRESH` などを変えてコミットします。次の初期値から反映されます。
過去分と比べるときは、変えた日をメモしておいてください(meta.json にも目安の値が記録されます)。

### 表示範囲を変える
`diag.py` の `DOMAIN` を変え、`batch/scripts/make_coast.py` で `web/coast.json` を、
`batch/scripts/make_terrain.py` で `web/terrain.png` を作り直します(MSMの地上ファイルが1つ必要です)。
`terrain.png` の格子がデータと合わないときは、山岳波と重力波の区別をせず、すべて地形性として扱います。画面の範囲ボタンは `web/index.html` の `VIEWS` です。
MSMの範囲(北緯22.4〜47.6度、東経120〜150度)より外には広げられません。

### 手元で1回分を計算する
```bash
cd batch
source scripts/rish_ca.sh
python -m turbmap.main --init 2026102009 --out ../out/data
cd .. && python -m http.server 8000
# http://localhost:8000/web/?data=/out/data/ で表示を確かめる
```
