# 計算方法とデータ形式

## 入力

- 気象庁 MSM の気圧面データ(1つの初期値につき1ファイル、予報33時間分、3時間ごと)
- 気象庁 MSM の地上データ(同じく1ファイル、毎時)。地上気圧と1時間降水量を、揺れる雲の評価に使います
- 格子:経度0.125度 × 緯度0.1度。使う範囲は北緯22.4〜46度、東経120〜147度(217×237マス)
- MSMの FT=0(初期値)は鉛直流がゼロなので、FT=3〜33 の11時刻を計算します

## 層

上下2つの気圧面のあいだを1つの層として計算します。

| 層 | 気圧面 | 中央の高度 |
|---|---|---|
| 1 | 700–600hPa | FL119 |
| 2 | 600–500hPa | FL161 |
| 3 | 500–400hPa | FL210 |
| 4 | 400–300hPa | FL269 |
| 5 | 300–250hPa | FL321 |
| 6 | 250–200hPa | FL363 |
| 7 | 200–150hPa | FL415 |

中央の高度は、2面の気圧の対数平均を標準大気の気圧高度に換算したものです。
画面で選んだFLの値は、上下2つの層の値を直線で補間して出します。

## 要素と「並」の目安

各要素の値を目安で割り、「並=1.0」の強さの指数にします。

| 要素 | 計算 | 並の目安 |
|---|---|---|
| 波(山岳波・重力波) | 鉛直流(m/s)から約60kmより大きい動きを除いた揺らぎの、5マス四方の標準偏差 σw。地形に関係なく、鉛直流の細かい揺れ全般を拾う(山岳波か重力波かは、総合の計算で地形の影響圏から区別する) | 0.25 m/s |
| 慣性不安定 | 絶対渦度/f。0.25のとき0、−0.25のとき1になるよう変換 | −0.25 |
| 変形場 | Ellrod TI1 = VWS × 変形(10⁻⁷ s⁻²) | 8 |
| 低リチャードソン数 | 0.75 ÷ Ri(Ri = N² ÷ シアー²) | Ri 0.75 |
| VWS(参考表示) | 上下の風の差 ÷ 層の厚さ(kt/1000ft)。色には混ぜず、総合の割り引き・上乗せの条件に使う。低RiとTI1の式にも含まれる | 6 |
| 対流 | √(CAPE/500 × 対流の兆候)× 雲の柱の重み。対流の兆候は max(前後1時間の雨の最大(周囲約25km)/10mm/h, 850〜300hPaの雲の中(相対湿度90%以上)の上昇流の最大/1m/s)。乾いた空気の上昇流(山岳波など)は対流の兆候に数えない。雲の柱の重みは、層のうち自由対流高度〜平衡高度にかかる割合+雲頂の上(雲頂気圧の1割、約2,000ft)にかかる割合×0.6。周囲約50kmにも半分の強さで広げる | 1 |
| 雲中の湿潤不安定 | 飽和度(氷相対湿度85%で0、95%で1)× 湿潤成層(g/θe × dθe/dz)のマイナスの大きさ/6×10⁻⁵。300hPaより上は湿度が欠測なので「データなし」 | 1 |
| 氷相対湿度 | 層の平均の相対湿度を氷に対する値に換算(雲の目安)。**MSMの湿度が実データなのは300hPaまで。250hPa以上の層(中央FL321以上)は欠測として値255を入れ、画面では「データなし」にする** | — |

風・気温・高度には、計算前に約15kmの平滑化をかけています。

## 総合の揺れやすさ(ブラウザで計算)

鉛直流の揺らぎ(σw)は、そのままでは揺れではなく空気の波です。波が砕けると揺れになるので、高い高度では、他の不安定要素と組み合わさらない限り評価を下げます。

1. **波の扱い**
   - **地形の影響圏**(`web/terrain.png`):標高400m超の場所と、その周辺約50kmを1(0〜1)にしたもの。地形の高さは、MSM地上データの海面気圧と地上気圧の差から出した目安です。
   - 影響圏の中の波を「山岳波」、外の波を「重力波」(ジェット・前線・対流が作る波)として分けます(影響圏の割合 zf で連続的に配分)。
   - 単独での評価 mwE = 山岳波×高度係数 + 重力波×0.35。高度係数はFL120で1.0、FL200以上で0.2(その間は直線)。
   - 他の要素と組み合わさるときの波の強さ mwS = 山岳波 + 重力波×0.6(高度係数は掛けない)。
   - 「CAT+揺れる雲」のときは、対流の上昇流・下降流も鉛直流の揺らぎとして現れるので、対流がある場所の重力波の分を差し引く(重力波 × (1 − min(1, 対流/0.8)))。同じ現象の二重計上を防ぐため。
2. **割り引く**
   - 低Ri:シアーが弱いとき、VWS指数/0.6 倍(最小0.3倍)
   - 慣性不安定:低Ri指数が0.5未満かつVWS指数が0.5未満のとき0.5倍
   - 変形場:単独の評価は0.5倍(独立した揺れの原因ではないため)。さらにVWS指数が0.3未満のとき0.6倍
   - **変形場による低Riの補正**:低Riの指数に min(1.5, 1 + 0.5×変形場の指数) を掛ける。変形場が強い所では、前線帯がモデルの格子や層より鋭くなり、モデルのRiは実際より大きめに出るため。補正後の低Riを、割り引き・土台・上乗せのすべてに使う
3. **揺れる雲**(画面で「CAT+揺れる雲」を選んだとき):対流と雲中の湿潤不安定を、土台の候補と上乗せに加える。
   CAPEを計算するときは、1000〜700hPaのうち相当温位が最も高い(地上より上の)空気を持ち上げる(最も不安定な空気のCAPE)。
4. **土台**:mwE・慣性不安定・変形場・低Ri(・対流・雲中の湿潤不安定)のうち最大のもの + 2番目×0.2
5. **上乗せ**(それぞれ「条件」を満たすとき、弱い方 × 係数)

   | 組み合わせ | 条件 | 係数 |
   |---|---|---|
   | 低Ri × VWS | 両方0.6以上 | 0.35 |
   | 波(mwS) × 低Ri | 両方0.6以上 | 0.4 |
   | 波(mwS) × VWS | 両方0.6以上 | 0.25 |
   | 波(mwS) × 慣性不安定 | 両方0.6以上 | 0.25 |
   | 波(mwS) × 変形場 | 両方0.6以上 | 0.2 |
   | 慣性不安定 × 低Ri | 両方0.6以上 | 0.25 |
   | 対流 × VWS | 両方0.6以上 | 0.25 |
   | 対流 × 慣性不安定 | 両方0.6以上 | 0.2 |
   | 雲中の湿潤不安定 × VWS | 両方0.6以上 | 0.25 |

6. 区切り:0.5 弱、0.8 並、1.2 並〜強、1.6 強

変形場の扱いの変更(低Riの補正に変更、単独は0.5倍、「変形場×VWS」の上乗せを廃止)の試算では、FL210〜360の「並」以上の面積は、10月20日で2〜4ポイント減り、10月15日はほぼ同じでした。外れた場所の約4〜6割は、変形場だけが強くRiが低くない場所でした。

10月20日09UTC初期値の試算では、雨3mm/h以上の格子のうち、CAPEが100J/kg未満の層状の雨では対流の指数がほぼ0(FL321で平均0.00〜0.01)、CAPEが500J/kg以上の雨では平均0.7〜1.2でした。

係数と高度係数は、考え方を数値にした仮の値です。
2026年10月20日・15日のデータで試算すると、旧方式(波をそのまま土台に使う)に比べて、
FL160〜270で「並」以上の面積が、波が強かった10月15日で約35〜50%、10月20日で約10〜20%減りました。
旧方式で「山岳波」としていた強い波の約半分は、地形の影響圏の外にありました。

## 出力データ

R2 のバケット(画面からは `/data/` 以下)に次の形で置きます。

```
index.json                    一覧(新しい順)
runs/2026102009/meta.json     初期値ごとの情報
runs/2026102009/ft03.png      FT=3 の数値データ
runs/2026102009/ft06.png      …(FT=33 まで11個)
```

### index.json
```json
{"version":1,"updated":"2026-10-20T16:13Z","retention_days":60,
 "runs":[{"init":"2026102009","init_iso":"2026-10-20T09:00Z","ft":[3,6,…],"valid":["2026-10-20T12:00Z",…]}]}
```

### meta.json の主な項目
| 項目 | 内容 |
|---|---|
| `ft`, `valid` | 予報時間と対象時刻(UTC) |
| `files` | 予報時刻ごとのファイル名 |
| `layers`, `mid_fl` | 層の気圧面と中央の高度 |
| `lat0`, `lon0`, `dlat`, `dlon`, `ny`, `nx` | 格子。`lat0` は北端で `dlat` は負 |
| `elems` | 要素の並び `["mw","ii","df","ri","vws","rhi","cv","mi"]`(古い形式のデータは `cv`・`mi` なし) |
| `missing_elems` | 300hPaより上を「データなし」(255)にする要素 `["rhi","mi"]` |
| `aux`, `aux_scale` | 補助の量 `["cape","el_fl","rain","wup"]` と、画素値に掛ける係数(J/kg、FL、mm/h、m/s) |
| `surface` | 地上ファイル(雨)を使ったか |
| `scale`, `missing` | 0.01(画素値×0.01 が指数)。画素値255は「データなし」(氷相対湿度の上空の層) |
| `rhi_valid_max_fl`, `rhi_valid_layers` | 氷相対湿度が使える上限(FL301)と層の数(4) |
| `thresholds` | 計算に使った「並」の目安 |

### ftXX.png
- 8ビットのグレースケールPNG(幅4096)。画像ではなく数値の入れ物です。
- 画素を左上から順に読むと、`[層][要素][緯度(北→南)][経度(西→東)]` の順に並び、そのあとに補助の量 `[量][緯度][経度]` が続きます(末尾は0で埋めています)。
- 値は指数×100(0〜255)。2.55以上は255に切りそろえています。
- 位置 `(層 l, 要素 e, 行 j, 列 i)` の値は、`((l*要素数 + e)*ny + j)*nx + i` 番目の画素です。

## 3D表示と鉛直断面(ブラウザで計算)

どちらも、バッチが作った数値データ(7層)から、ブラウザ内で作ります。バッチやR2のデータは変わりません。

- **体積データ**:FL120〜FL410を10(1000ft)刻みの30段に、層の値を直線で補間します。各段・各マスで、総合(または選んだ1要素)の値を計算します。約217×237×30=約150万個です。
- **3D表示**:three.js のボリュームレンダリング(レイマーチング)です。値がしきい値(既定0.8=並)以上の領域を、半透明の塊で描きます。色は2D地図と同じです。
  - 高さの強調(既定40倍)、表示する高度の範囲、しきい値、濃さを画面で変えられます。
  - 水平は約3,000km、高さは約9kmなので、高さを強調しないと平らな板に見えます。
  - 地形の高さは使っていません。地面は平らな板に海岸線を描いています。
- **鉛直断面**:2D地図で点を2〜8点クリックし、点を結んだ折れ線に沿って約8km間隔でサンプルします。各サンプル点の値を、水平は双一次補間、高さ方向は10刻みの値の補間で求め、横軸が距離、縦軸がFLの図にします。
  - 断面に描けるのは、揺れやすさの要素の値だけです。風や気温は、バッチのデータに含まれないので描けません(前線の傾きを等温線で見たい場合は、バッチのデータに気温・風を追加する必要があります)。
  - 元データは7層なので、縦方向の細かい構造は出ません。

## 空港とアビーム

- 表示する空港は `web/airports.json`(IATAコード・名前・緯度・経度)で、追加・削除できます。
- 断面の横軸のアビーム:経路(折れ線)の各区間に空港を垂直に投影し、経路からの横距離が230km以内の空港を対象にします。経路の両端より先にある空港は、端から50kmまでを対象にします。
- 横軸上で100km以内に複数の空港が並ぶときは、経路からの横距離が小さい空港だけを残します。
- 値は `index.html` の `ABEAM_MAX`(230)、`ABEAM_SEP`(100)、`ABEAM_END`(50)で変えられます。
